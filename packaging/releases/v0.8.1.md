This release is about duplicates: the same advert reposted with an edited title,
and the same advert open in several cities. It also makes a re-score follow the
candidates instead of the table, and adds one source.

### Duplicates

- **A repost with an edited title** is now one advert. arbeitnow published the
  same Girona role twice, two days apart, as the same title with "Hybrid"
  inserted and a new slug. The same-board pass compared titles with a prefix
  test, which cannot see an insertion in the middle; a second pass now requires
  the same board, employer and place, one title's words contained in the other,
  and bodies that agree on at least 90% of their words. A number-only edit counts
  too, because sifamo changed "bis zu 90% remote" to "95%". The more specific
  title is kept.
- **One advert open in several cities** is one advert. TOUGH advertised one job
  as "Essen, Würzburg" on Stepstone and "Würzburg oder Essen" on Jobware, and a
  five-city advert sat on Stellenanzeigen as "Darmstadt, Köln, Ludwigsburg,
  München, Berlin" while XING printed only "Berlin". A location is a set of
  cities now, split on commas, slashes, pipes, "oder", "und" and ampersands,
  with a country code dropped, and two rows match when their city sets
  intersect.
- Two rules that had already merged different jobs were caught and closed. The
  body alone is not evidence: vivenu advertises two different roles with the
  same boilerplate body word for word, so the title must be nested as well. A
  shared prefix is not evidence either: "Senior Account Executive" and "Senior
  Account Executive - Midwest" were merged by the old rule, so the prefix path
  now accepts only a board's 100-character title cut.
- Employers shorter than four characters (n8n, B12, SAP) escaped the same-board
  pass entirely; the floor is three now. Merging also repoints rows that pointed
  at the copy being hidden, and the store's existing chains were flattened.

### Store and scoring

- A re-score reads advert bodies only for the rows whose verdict depends on the
  text. The title, employer, place and date gates never read the advert, so the
  first pass scores every row with an empty body (58,987 rows in about six
  seconds) and only the candidates go to a second pass that reads bodies in
  chunks. A warm re-score takes about 13 seconds instead of 37.
- Term matching stopped running one regex per term per posting. Single-word
  terms match against a word set, or with a substring search and a boundary
  check, and only terms with spaces or punctuation keep the regex. A test pins
  the fast paths to the per-term answer, because a re-score must not move a
  score.
- A scan removes what can never be shown: rows filtered as stale by date, and
  hidden rows older than `preferences.retention_days` (30 by default, editable
  in Settings). Saved, applied and visible rows are never touched, and a
  duplicate the person acted on survives its keeper.
- A row whose title matches nothing keeps a 300-character teaser instead of the
  whole advert: it can never be shown whatever its body says, and the fill job
  reads the body again if the row ever becomes a candidate.
- Measured on the real store: 58,987 rows and 434 MB became 31,116 rows and
  283 MB.

### Sources

- **The Max Planck Society's own jobboard** joins the academic set, filed as the
  employer's own board, so duplicates prefer it over an aggregator's copy. It is
  not a keyword search: the board lists every open position, five on the page
  and the rest through an HTML fragment endpoint, and a scan walks it newest
  first, 20 per request, with the profile filtering afterwards. Live: 51
  postings fetched and 45 stored in the default profile.
- The scan summary no longer counts a match twice when a teaser had already put
  a row in the list and the detail probe re-scored it.

### Documentation

- The README source table lists all 54 boards, including the UK market the
  Settings screen has. `englishjobs` and `talent.com` were removed in 0.8.0 and
  are no longer listed; `interamt`, `maxplanck`, `jobsacuk`, `theunijobs` and the
